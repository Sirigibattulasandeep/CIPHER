# SENTRIX integration contract

The canonical contracts are exported from `src/lib/contracts.ts`. Detection modules should use `Finding` and `findingSchema` when adding their findings route: `source` is one of `SOCIAL`, `MOBILE_APP`, `WEBSITE`, or `DOMAIN`; `riskScore` and `confidence` are integers from 0–100. All API failures use `{ error: { code, message, fields? } }`.

Brand endpoints are `GET /api/brands?q=&industry=&monitoring=&sort=name|updatedAt&direction=asc|desc&page=1&pageSize=20`, `POST /api/brands`, and `GET/PATCH/DELETE /api/brands/:id`. List responses are `{ items, total, page, pageSize, totalPages }`. POST/PATCH bodies must satisfy `brandSchema`; successful create returns 201 and the brand, successful update returns 200, delete returns 204. Detection owners should use `brandId` from the brand selector and never accept an organisation ID from the browser. The current development adapter persists to `data/brands.json`; production should configure `DATABASE_URL` and replace the adapter with Prisma repository methods.

Brand DNA utilities are exported from `src/lib/brand-dna.ts`. `matchBrandName`, `matchOfficialDomain`, `matchHandle`, and `matchApplication` return explainable matches only; a match is an indicator, not a fraud verdict. Domain comparison permits the official hostname and its subdomains, while rejecting suffix tricks such as `example.com.attacker.test`.

Organisation isolation is represented by `organisationId` on every tenant model. The server-only context helper in `src/lib/auth.ts` currently supplies `org_demo` for the local demo; replace it with the established session provider before production deployment and pass its organisation id into every repository query. Never expose database credentials or server-only environment variables to client components.
