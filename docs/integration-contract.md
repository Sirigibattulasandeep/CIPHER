# SENTRIX integration contract

The canonical contracts are exported from `src/lib/contracts.ts`. Detection modules create findings through `POST /api/findings` using the shared `Finding` schema. `source` is one of `SOCIAL`, `MOBILE_APP`, `WEBSITE`, or `DOMAIN`; `riskScore` and `confidence` are integers from 0–100. API failures use `{ error: { code, message, fields? } }`.

The Social & Apps scanner accepts `POST /api/monitoring/scan` with `{ brandId, kind: 'social' | 'apps', records }`. It returns shared `Finding` objects, which the workspace persists through `POST /api/findings`. The public scan route assigns `IMPORTED` or `DEMO` origin and reliability on the server; client records cannot claim `CONNECTED` provenance or raise their reliability. A future authorized connector must call the analysis layer through a server-owned path to assign `CONNECTED` provenance.

Brand endpoints are `GET /api/brands?q=&industry=&monitoring=&sort=name|updatedAt&direction=asc|desc&page=1&pageSize=20`, `POST /api/brands`, `GET/PATCH/DELETE /api/brands/:id`, and `POST /api/brands/:id/assets`. List responses are `{ items, total, page, pageSize, totalPages }`. POST/PATCH bodies must satisfy `brandSchema`; successful create returns 201 and the brand, successful update returns 200, and delete returns 204. Official asset requests satisfy `officialAssetSchema`. Detection owners use `brandId` from the brand selector and never accept an organisation ID from the browser.

Finding vertical-slice endpoints include `POST /api/findings`, `GET /api/findings/:id`, `POST /api/findings/:id/evidence`, `PATCH /api/findings/:id/status`, and `PATCH /api/findings/:id`. Finding persistence, evidence, and status-history behavior is exercised in `tests/integration.test.ts`.

Brand DNA utilities are exported from `src/lib/brand-dna.ts`. `matchBrandName`, `matchOfficialDomain`, `matchHandle`, and `matchApplication` return explainable matches only; a match is an indicator, not a fraud verdict. Domain comparison permits the official hostname and its subdomains, while rejecting suffix tricks such as `example.com.attacker.test`.

The development adapters persist brands to `data/brands.json` and findings to `data/findings.json`; production should configure `DATABASE_URL` and replace the adapters with Prisma repository methods. Organisation isolation is represented by `organisationId` on each tenant model. The server-only context helper in `src/lib/auth.ts` currently supplies `org_demo` for the local demo; replace it with the established session provider before production and pass its organisation ID into every repository query. Never expose database credentials or server-only environment variables to client components.
